What it does
Unity apps incorrectly set the CPU affinity to the max capacity cores. UnityFix sets two kernel parameters so those apps use the cores you choose.
sched_lib_name: comma separated list of libraries (.so). If an app has one of them loaded, the kernel treats it as a library based app (Unity games load libunity.so).
sched_lib_mask_force: CPU mask (bit N = CPU N, 0-255) that the kernel uses as the CPU affinity of those apps instead of the one they ask for.
CPU cores
Applies the mask right away and re-applies it at every boot.
255 = Use all cores [0-7]
240 = Use 4 cores [4-7]
192 = Use 2 cores [6-7]
128 = Use only CPU 7
Libraries
Libraries written to sched_lib_name (comma separated). Apply writes the list right away and keeps it at every boot.
Restore default: libunity.so, libfb.so
Check UnityFix
Shows the mask and the library list the kernel is using now.
Log
After each boot the module watches the values for 5 minutes and fixes them if your ROM changes them. Every change is saved with date and time in /storage/emulated/0/unityfix_log.txt (a new log is created on every boot).
If the internal storage is not available, it is saved in /data/adb/unityfix/unityfix_log.txt.
LibChecker
The LibChecker app is recommended to see the libraries of your app (game).
